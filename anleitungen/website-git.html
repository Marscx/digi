Website veröffentlichen: Git, GitHub und Hosting

Eine Website aus Dateien bauen, lokal testen, mit Git versionieren, auf GitHub speichern und bei jedem Push automatisch auf einem Hosting veröffentlichen.

  • Zeitca. 90–120 Minuten
  • Schwierigkeitmittel bis schwierig
  • GerätComputer (Mac oder Windows)
  • KostenGit und GitHub gratis, Hosting je nach Anbieter (GitHub Pages gratis)
Vorab einrichtenInstalliere Git vorab (Schritt 4), lege ein gratis GitHub-Konto an und halte einen Texteditor bereit. Wenn du ein eigenes Hosting hast, brauchst du seine Zugangsdaten. So bleibt am Praxistag mehr Zeit zum Ausprobieren.

1

Basics: Was ist das, was brauche ich?

10 Min.

Eine Website aus Dateien (HTML, CSS) kannst du von einer KI schreiben lassen. Damit nichts verloren geht und du jederzeit zurück kannst, verwaltest du die Dateien mit Git (Versionsverwaltung). GitHub ist der Ort im Internet, an dem deine Git-Ablage (das Repository) liegt. Ein Hosting ist der Server, der die Seite für Besuchende ausliefert.

Der Weg: Dateien auf dem Computer → Git (Commit) → GitHub (Push) → Hosting holt sich die neue Fassung automatisch. So ist auch diese Seite hier veröffentlicht.

Das brauchst du

  • Computer mit Mac oder Windows und einem Browser
  • Einen Texteditor (besser ein Code-Editor wie Visual Studio Code)
  • Ein kostenloses Konto bei github.com
  • Für Teil 6: ein Hosting mit Git-Funktion (zum Beispiel Plesk) oder GitHub Pages (gratis)
  • Einen Zugang zu einer KI
Neu im Terminal?Für den Testserver und für Git brauchst du das Terminal. Die ersten Befehle und das Öffnen unter Mac und Windows stehen in der Anleitung Terminal: die ersten Befehle. Lies sie zuerst, wenn du das Terminal noch nie benutzt hast.
Öffentlich oder privatEin öffentliches Repository kann jede Person lesen. Lege nie Passwörter, Schlüssel oder private Daten hinein. Für Websites, die sowieso öffentlich sind, ist das kein Problem.
2

Die Website lokal bauen

25 Min.
  1. Schreibe in fünf Sätzen auf: Wer bist du, was bietest du an, für wen, und was sollen Besuchende tun?
  2. Gib der KI diese Angaben mit einem klaren Auftrag (siehe unten).
  3. Lege einen neuen Ordner an, zum Beispiel meine-website. Speichere den Code der KI darin als index.html.
  4. Doppelklicke auf die Datei. Sie öffnet sich im Browser. Prüfe auch die schmale Handyansicht, indem du das Fenster verkleinerst. Wie du die Seite auf einem Testserver öffnest, folgt im nächsten Schritt.
  5. Verbessere die Seite in drei Runden: Sag der KI kurz, was du ändern willst, ersetze den Code, lade die Seite neu.
Schreibe mir eine einfache Website mit einer Seite: Abschnitte Über mich, Angebote und Kontakt. Schlicht, gut lesbar auf dem Handy, ohne externe Schriften oder Skripte. Liefere eine einzige Datei index.html mit eingebautem CSS.
Über mich: [fünf Sätze]
Angebote: [drei Stichpunkte]
Kontakt: [E-Mail]
DatenschutzGib der KI keine privaten Angaben anderer Personen, die nicht öffentlich werden sollen.
3

Lokal testen: der Testserver

15 Min.

Ein Doppelklick auf index.html reicht für eine einfache Seite. Sobald Seiten auf andere Dateien verweisen (Unterseiten, Schriften, Skripte), verhält sich ein lokaler Webserver wie das spätere Hosting. Dann zeigt dir der Browser genau das, was Besuchende sehen. Teste deshalb, bevor du etwas hochlädst. Für Seiten aus reinem HTML, CSS und JavaScript reicht ein eingebauter Testserver, du musst nichts weiter installieren.

Der eingebaute Testserver

  1. Öffne das Terminal im Ordner deiner Website (cd meine-website).
  2. Starte den Testserver. Auf dem Mac geht python3, auf Windows meist py:
python3 -m http.server 8000
  1. Öffne im Browser http://localhost:8000. Die Seite wird von deinem Computer ausgeliefert.
  2. Beende den Server mit Ctrl+C im Terminal. Nach einer Änderung lädst du die Seite im Browser neu.
Alternative im Code-EditorIn Visual Studio Code gibt es die Erweiterung «Live Server». Sie startet einen Testserver mit einem Klick und lädt die Seite bei jeder Änderung automatisch neu.
Nur für dichEin lokaler Testserver ist nur auf deinem Computer erreichbar. Gib nie ein Passwort auf einem lokalen Testserver ein, das du anderswo brauchst. Schliesse den Server, wenn du fertig bist.

4

Git installieren und den ersten Commit machen

25 Min.
  1. Installiere Git von git-scm.com/downloads. Auf dem Mac geht auch: Terminal öffnen und git --version eingeben, macOS bietet die Installation dann selbst an.
  2. Öffne das Terminal (Mac) oder die Eingabeaufforderung bzw. «Git Bash» (Windows) und wechsle in deinen Ordner, zum Beispiel mit cd meine-website.
  3. Stelle dich einmalig vor, damit Git deine Änderungen beschriften kann. Verwende die Adresse, die du auch bei GitHub angibst (oder die «noreply»-Adresse von GitHub, wenn du deine nicht zeigen willst).
git config --global user.name "Dein Name"
git config --global user.email "du@beispiel.ch"
  1. Lege das Repository an, nimm alle Dateien auf und speichere die erste Fassung:
git init -b main
git add .
git commit -m "Erste Fassung der Website"
Ohne TerminalWenn dir das Terminal zu technisch ist, gibt es GitHub Desktop. Es macht dieselben Schritte mit Knöpfen. Du kannst die KI auch bitten, dir jeden Befehl zu erklären, bevor du ihn eingibst.

Commit heisst: eine Fassung des Ordners mit einer kurzen Beschreibung speichern. Du kannst später jede alte Fassung ansehen und zurückholen.

5

GitHub: Repository anlegen und hochladen

20 Min.
  1. Melde dich bei github.com an und klicke auf New repository.
  2. Gib einen Namen ein (zum Beispiel meine-website), wähle Public und lege keine README-Datei an (dein Ordner hat schon Inhalt). Klicke auf Create repository.
  3. GitHub zeigt dir die Adresse deines Repositorys. Verbinde deinen Ordner damit und lade ihn hoch. Ersetze DEIN-NAME und meine-website:
git remote add origin https://github.com/DEIN-NAME/meine-website.git
git push -u origin main
  1. Beim ersten Push fragt Git nach deiner Anmeldung. Folge den Hinweisen im Fenster oder in GitHub Desktop. Gib dein GitHub-Passwort nie in einen Chat mit der KI ein.
  2. Lade die Seite deines Repositorys neu. Du siehst jetzt deine Dateien.
Anmeldung bei GitHubGitHub akzeptiert beim Push kein normales Passwort mehr. Die Anmeldung läuft über den Browser, GitHub Desktop oder ein «Personal Access Token». Der Hinweis im Terminal sagt dir, was zu tun ist.
6

Veröffentlichen: Weg A mit GitHub Pages, Weg B mit eigenem Hosting

30 Min.

Weg A: GitHub Pages (gratis, am einfachsten)

  1. Öffne dein Repository auf GitHub und gehe zu Settings → Pages.
  2. Wähle bei Source «Deploy from a branch», Branch main und Ordner / (root). Speichere.
  3. Nach etwa ein bis zwei Minuten zeigt GitHub oben die Adresse deiner Seite (in der Form DEIN-NAME.github.io/meine-website).

Weg B: eigenes Hosting mit Plesk (so ist diese Seite veröffentlicht)

Viele Hoster (zum Beispiel Metanet) bieten die Verwaltung Plesk mit einer Git-Funktion. Die Menüs heissen je nach Hoster etwas anders. Die Schritte sind im Kern:

  1. Lege bei deinem Hoster die Domain oder Subdomain an, auf der die Seite laufen soll.
  2. Öffne in Plesk die Domain und wähle Git. Wähle Repository hinzufügen (Add Repository) und gib die Adresse deines GitHub-Repositorys an (https://github.com/DEIN-NAME/meine-website.git).
  3. Wähle den Branch main und den Modus Automatisches Deployment (bei Plesk: «Automatic»). Bei einem öffentlichen Repository brauchst du keinen Schlüssel.
  4. Plesk zeigt dir eine Webhook-URL. Kopiere sie.
  5. Gehe in GitHub zu deinem Repository: Settings → Webhooks → Add webhook. Füge die URL bei Payload URL ein, wähle als Content type application/json und als Ereignis nur Push. Speichere.
  6. Klicke in Plesk einmal auf Pull Updates (Deploy), damit die erste Fassung auf dem Server liegt.
TestGehe in GitHub zum neuen Webhook und öffne «Recent Deliveries». Ein grüner Haken heisst: Plesk hat die Nachricht erhalten.
7

Kleine Umsetzung: eine Änderung veröffentlichen

15–20 Min.

Auftrag: Ändere einen Satz auf deiner Seite und bringe die Änderung bis ins Internet.

  1. Ändere in index.html einen Satz und speichere die Datei.
  2. Prüfe die Änderung lokal auf deinem Testserver (http://localhost:8000).
  3. Speichere eine neue Fassung und lade sie hoch:
git add .
git commit -m "Einstiegssatz geändert"
git push
  1. Warte etwa eine Minute und lade die öffentliche Adresse deiner Seite neu (Cmd+Shift+R oder Strg+F5).

Fertig, wenn…

Wenn du weitermachen willst

  • Zurück zu einer alten Fassung: git log --oneline zeigt alle Fassungen. Frag die KI, wie du eine davon wiederherstellst.
  • Mit der KI im Editor arbeiten: Programme wie Claude Code können Dateien direkt ändern und Commits vorbereiten. Die Prüfung und den Push machst du.
  • Eigene Domain: Bei Weg B richtest du die Domain bei deinem Hoster ein. Bei GitHub Pages gibt es dafür eine Einstellung unter «Custom domain».
!

Stolpersteine

  • Nichts Geheimes ins Repository: Bei einem öffentlichen Repository sind alle Dateien und alle alten Fassungen für alle sichtbar. Ein einmal hochgeladenes Passwort gilt als verloren.
  • Webhook zeigt rot: Meist stimmt die URL nicht oder Plesk ist nicht auf den richtigen Branch eingestellt. Prüfe «Recent Deliveries» in GitHub.
  • Seite zeigt noch die alte Fassung: Lade neu ohne Zwischenspeicher (Cmd+Shift+R oder Strg+F5) und warte eine Minute.
  • Push abgelehnt: Meist fehlt die Anmeldung bei GitHub oder der Branch heisst anders. Kopiere die Fehlermeldung zur KI und lass sie dir erklären.
  • Suchmaschinen: Eine neue Seite ist öffentlich. Möchtest du sie noch verstecken, ist ein privates Hosting oder eine Sperre nötig. Frag deinen Hoster.
  • Impressum und Datenschutz: Eine öffentliche Seite braucht beides.
